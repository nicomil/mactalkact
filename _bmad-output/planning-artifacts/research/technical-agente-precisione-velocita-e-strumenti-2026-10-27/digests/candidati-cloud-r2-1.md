## Claims

- Anthropic esclude esplicitamente l'Agent SDK (candidato B) dall'uso con login abbonamento: «Developers building products or services ... including those using the Agent SDK, should use API key authentication». Il candidato B supera il gate "nessuna API key obbligatoria" solo se l'SDK gira sul login dell'utente, che la pagina legale scoraggia; l'Help Center però conferma che con il login del piano «the Claude Agent SDK and `claude -p` still draw from your subscription limits», quindi tecnicamente funziona ma la posizione di policy è ambigua. | https://code.claude.com/docs/en/legal-and-compliance ; https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan | Anthropic | pub n/d / 2026-10-07 | accessed 2026-10-27 | confidence high | class security
- `claude -p --bare` non usa l'abbonamento: «Set `ANTHROPIC_API_KEY` before running it, because bare mode doesn't use your subscription login» e «In bare mode, Claude Code never reads OAuth credentials or the system keychain». Per il gate "senza API key" l'app deve quindi evitare `--bare` (perdendo il risparmio di startup) oppure accettare la API key. Anthropic: «`--bare` is the recommended mode for scripted and SDK calls, and will become the default for `-p` in a future release» — rischio futuro per il percorso abbonamento. | https://code.claude.com/docs/en/headless | Anthropic | pub n/d (pagina viva) | accessed 2026-10-27 | confidence high | class security
- Restrizione dell'engine ai soli tool MCP dell'app con Claude Code: `--tools ""` disabilita tutti i built-in («Use `""` to disable all»; «The flag doesn't affect MCP tools»), `--strict-mcp-config --mcp-config <file>` «Only use MCP servers from `--mcp-config`, ignoring all other MCP configurations», `--disallowedTools "mcp__*"` rimuove tutti gli MCP se servisse. Esiste anche `--restricted` (rimuove i tool che eseguono comandi/codice e WebFetch, confina i file tool alle working directories, carica solo managed settings). Senza `--bare`, un run `-p` «connects the servers in its `.mcp.json`, even in a folder you've never trusted» e «shows no workspace trust dialog». | https://code.claude.com/docs/en/cli-reference ; https://code.claude.com/docs/en/headless | Anthropic | pub n/d | accessed 2026-10-27 | confidence high | class security
- Multi-turno in un solo processo `claude -p`: esiste `--input-format stream-json` («Specify input format for print mode (options: `text`, `stream-json`)»), con `--max-turns` che «With `--input-format stream-json`, a message still queued when the limit ends a turn stays queued and starts a new turn with its own limit», e `--replay-user-messages` (richiede input e output stream-json). Quindi un processo lungo che riceve più messaggi utente è supportato; i messaggi però appartengono alla stessa sessione/contesto, non sono richieste indipendenti. Per richieste separate restano `--continue`/`--resume <session_id>` (nuovo processo) e il costo riportato «reports the conversation's whole total, earlier runs' spend included». Nessuna nota ufficiale trovata su "shared prompt cache" tra sessioni. | https://code.claude.com/docs/en/cli-reference ; https://code.claude.com/docs/en/headless | Anthropic | pub n/d | accessed 2026-10-27 | confidence medium | class pattern
